一、体系架构总览

八个环节环环相扣，Python 代码是贯穿始终的主线，AI Agent 在每一环都有明确的介入点。

两条总原则

  • 研究驱动学习：每个技能用真实研究任务掌握，不上编程课
  • AI 结对：研究者提需求、审结果、做判断；AI 写代码、做执行

三条铁律

  • 原始数据只读，绝不在 Excel 手改
  • 患者数据脱敏后才交给 AI
  • 统计决策人来定，代码 AI 写，结果人来审

效率曲线

  • 1–3 个月：学习阵痛期，效率下降
  • 3–6 个月：追平原工具链
  • 6 个月+：稳定反超，AI 红利持续放大

保留的商业 / 免费软件

软件 使用场景

JASP 结果交叉验证、教学

选装（按需启用）

  • ASReview：AI 辅助系统综述文献筛选（做 Meta 分析前必装）
  • jsPsych：深度定制网页实验
  • polars：百万行级数据加速
  • PyMC / bambi：贝叶斯分析
  • MNE-Python：EEG 分析
  • Taguette：质性访谈编码（替代 NVivo）
精简原则选装项不预装，项目需要时 uv pip install 即用，避免环境臃肿。

三、16 周学习路径

六阶段递进，每阶段用真实研究任务验收。真正的学习曲线是"向 AI 精确描述研究需求"的能力，而非背语法。

阶段 0–1 · 环境熟练（1–2 周）→ 数据清洗（3–4 周）

阶段 0 · 环境熟练

  • VS Code 打开文件夹 → 新建 .ipynb → 跑通第一行代码
  • 学会 uv pip install 包名 管理环境
  • AI 练习：把任何报错直接贴给 AI，把它当随身导师
  • 验收：独立打开 notebook、读入 CSV、查看数据

阶段 1 · 数据清洗（最重要的基本功）

  • 教材：拿一份自己已有的 SPSS 数据（.sav 用 pyreadstat 读入）
  • 任务：筛有效被试 → 反向题重编码 → 算量表总分 → 缺失值统计 → 导出 Parquet
  • AI 练习："q3、q7、q12 是 1–5 点反向计分，帮我重编码并计算总分"——重点训练读懂代码、核对结果
  • 验收：清洗结果与原 SPSS 处理完全一致
阶段 2–3 · 统计迁移（5–7 周）→ SEM 迁移（8–10 周）

阶段 2 · 统计迁移

  • 教材：选一篇自己已发表的论文，用代码重做全部统计
  • 覆盖：信度、t 检验、ANOVA+事后检验、相关、回归、卡方
  • 关键认知：pingouin 自带效应量/检验力/Bayes Factor，都要会解读（审稿加分项）
  • 进阶：重复测量用 mixed_anova；中介用 mediation_analysis
  • 验收：全部数字与原论文吻合，形成「常用分析模板 notebook」

阶段 3 · SEM 迁移

  • semopy 重做一个 CFA、一个中介/路径模型
  • 学会看 CFI / TLI / RMSEA / SRMR 并与 Mplus 输出对照
  • 掌握决策规则（见下方决策树）
  • 验收：semopy 与 Mplus 参数估计、拟合指标吻合
阶段 4–6 · 实验收数 → Quarto 写作 → 进阶

阶段 4 · 实验收数（11–12 周）

  • PsychoPy Builder 复刻经典范式（如 Stroop）+ 嵌入问卷
  • 上传 Pavlovia 跑通 设计→上线→收数→清洗 闭环
  • 纯问卷研究可延后，REDCap 建库优先

阶段 5 · Quarto 写作（13–14 周）

  • 把一篇成稿转成 Quarto：数字改为代码内联输出
  • 配好 Better BibTeX 引文（@citekey），渲染 Word 投稿
  • 体验目标：改数据后重新渲染，全文数字自动刷新

阶段 6 · 进阶（15 周+）

  • 项目需求触发：DuckDB 大数据、scikit-learn 预测模型
  • metafor 做 Meta 分析、ASReview 筛文献
  • 贝叶斯（bambi）、EMA 密集纵向数据

四、标准工作流（SOP）

研究者与 AI 的分工泳道：判断与决策在人，执行与文书在 AI。

四条 SOP 约定

项目启动

  • 复制标准目录模板 → git init → uv venv 锁环境
  • 放入 AGENTS.md 并按项目微调 → OSF 建项目

数据铁律

  • data/raw/ 只读，清洗只走脚本到 processed/
  • 绝不在 Excel 手改数据；标识符对照表存工作空间之外

分析铁律

  • 脚本头部注明：输入文件、分析目的、对应论文表/图
  • 关键结果投稿前用 JASP 交叉验证一次

AI 协作铁律

  • 统计决策人来定、代码 AI 写、结果人来审
  • 论文中 AI 生成内容按期刊政策声明
日常节奏每日：新文献随手入 Zotero、工作结束 Git 提交。每周：备份 data/、整理 notebook 保证可从头复跑。每项目节点：Quarto 渲染一次全文，检查数字一致性。

5.2 常用统计方法速查

研究问题 方法 代码入口
量表信度 Cronbach's α / McDonald's ω pg.cronbach_alpha(items)
两组比较 t 检验（不正态→Mann-Whitney） pg.ttest(x, y) / pg.mwu(x, y)
多组比较 ANOVA + 事后检验 pg.anova() + pg.pairwise_ttests()
重复测量 重复测量 ANOVA / 混合模型 pg.rm_anova() / statsmodels mixedlm
变量间关系 相关（含偏相关） pg.corr() / pg.partial_corr()
预测关系 线性 / Logistic 回归 statsmodels: smf.ols() / smf.logit()
中介效应 Bootstrap 中介分析 pg.mediation_analysis()
测量结构验证 EFA → CFA factor_analyzer → semopy
缺失值 多重插补 R mice（Rscript 调用）
样本量 功效分析 pg.power_ttest() / G*Power

5.3 核心代码模板

模板 A · 问卷数据清洗全流程（pandas） 
# 输入: data/processed/survey_deidentified.csv（已脱敏）
import pandas as pd, pyreadstat

df, meta = pyreadstat.read_sav("data/raw/old.sav")   # SPSS 历史数据迁移

# 1. 筛选有效被试
df = df[df["duration_sec"] > 180]                      # 作答时间过短
df = df[df[[f"q{i}" for i in range(1, 21)]].std(axis=1) > 0]  # 规律作答

# 2. 反向题重编码（1–5 点）
rev = ["q3", "q7", "q12"]
df[rev] = 6 - df[rev]

# 3. 维度分与总分
df["depression"] = df[[f"q{i}" for i in range(1, 10)]].sum(axis=1)
df["anxiety"]    = df[[f"q{i}" for i in range(10, 21)]].sum(axis=1)

# 4. 缺失与描述
print(df.isna().mean().sort_values(ascending=False).head())
print(df[["depression", "anxiety"]].describe())

df.to_parquet("data/processed/clean.parquet")          # 只写 processed
模板 B · 论文级统计报告（pingouin） 
import pingouin as pg

# 信度
alpha = pg.cronbach_alpha(data=df[[f"q{i}" for i in range(1, 10)]])

# 组间比较：输出自带效应量、检验力、Bayes Factor
aov = pg.anova(data=df, dv="depression", between="group", detailed=True)
post = pg.pairwise_ttests(data=df, dv="depression", between="group",
                          padjust="fdr_bh")          # 多重比较校正

# 前提假设检查（AI 常跳过，务必要求）
print(pg.normality(data=df, dv="depression", group="group"))
print(pg.homoscedasticity(data=df, dv="depression", group="group"))

# 中介分析（Bootstrap）
med = pg.mediation_analysis(data=df, x="stress", m="rumination",
                            y="depression", n_boot=5000)
模板 C · SEM（semopy，替代 Mplus 常规模型） 
import semopy

model = semopy.Model("""
# 测量模型
抑郁 =~ PHQ1 + PHQ2 + PHQ3 + PHQ4
焦虑 =~ GAD1 + GAD2 + GAD3 + GAD4
# 结构模型
抑郁 ~ 焦虑 + 社会支持
""")

model.fit(df)
res = model.inspect()
stats = semopy.calc_stats(model)      # CFI / TLI / RMSEA / SRMR 等
print(res); print(stats.T)
semopy.semplot(model, "output/sem_path.png")   # 路径图
模板 D · Python 调 R（Windows 推荐：Rscript 子进程） 
# analysis_lpa.R —— 用 mclust 做潜剖面分析

import subprocess

5.5 向 AI 下指令的三类范式

数据任务

给出变量含义、计分规则、筛选标准 → 要求输出 代码 + 结果 + 解释 三件套。

统计任务

说明研究设计（几组/是否配对/变量类型）→ 要求 推荐方法 → 给代码 → 解读输出 三步走。

审读任务

把 AI 的输出贴回去问："这个分析的前提假设是什么？我的数据满足吗？"

六、工作空间与配置边界

全局（装一次，永久生效）

  • uv · R+Rtools · VS Code · Quarto · Git · PsychoPy · JASP · G*Power
  • Zotero + Better BibTeX；zotero-mcp / ASReview（uv tool install）
  • R 全部包（全局库，项目共享）
  • MCP 配置（filesystem→research 根目录 · zotero · duckdb 共享库）

每个新项目（约 5 分钟）

  • 目录结构 + git init
  • uv venv 独立环境 + 安装 Python 包
  • 复制 AGENTS.md（自包含，按项目微调）+ .gitignore
  • 数据脱敏后入 processed/，raw 封存
授权给根目录，工作在子项目MCP filesystem 授权 research 根目录（一次覆盖所有项目）；但日常启动 Agent / 打开 VS Code 都在 子项目 层——AGENTS.md 才会加载、.venv 才被识别、Git 边界才清晰、误触他项目数据的概率最低。只有跨项目管理性任务（更新共享模板、备份）才回根目录。
数据安全的最后一道防线AGENTS.md 是"约定"而非"技术强制"。含患者标识符的数据最可靠的隔离方式：根本不放进 Agent 可见目录——标识符对照表存 research 根目录之外，processed/ 只放脱敏副本。
